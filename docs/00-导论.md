# 00 · 导论

## Agent设计理念

```text
Agent = 输入组织 + 约束设计 + 执行闭环 + 输出验收
```

这里用公式表达设计的组成和判断条件，方便观察，全是汉字可能有点乱，后续也都用符号了，我让AI写了一个符号说明。

### 符号说明

| 符号 | 中文读法 | 在本文中的含义 |
|---|---|---|
| `=` | 定义为、由……组成 | 表达设计组成或判断规则，不是数值计算 |
| `+` | 加上 | 将多个设计要素组合起来 |
| `∧` | 并且 | 所列条件必须全部满足 |
| `∨` | 或者 | 所列条件至少满足一个即可，也可以同时满足多个 |
| `→` | 然后、进入下一步 | 表示执行顺序或状态流转 |
| `…` | 继续重复 | 表示循环可以继续，直到满足停止条件 |
| `≠` | 不等同于 | 表示两个概念不能混为一谈 |

例如，`资料齐全 ∧ 检查通过`，读作“资料齐全，并且检查通过”，两项都要满足。

`已完成 ∨ 预算耗尽`，读作“已完成，或者预算耗尽”，任一项成立就可以停止；停止的原因仍需分别记录。

### 输入组织

```text
输入组织 = 任务指令 + 上下文

任务指令 = 目标 + 要求 + 示例
上下文   = 背景事实 + 参考资料 + 历史记录 + 当前状态
```

### 约束设计

```text
约束设计 = 场景边界 + 操作权限 + 执行规则 + 资源预算

场景边界 = 服务对象 + 适用范围
操作权限 = 允许的动作 + 允许的对象 + 授权条件
执行规则 = 必要步骤 + 冲突优先级 + 异常处理
资源预算 = 时间上限 + 费用上限 + 调用上限
```

### 执行闭环

```text
执行闭环 = 观察 → 决策 → 行动 → 检查 → 更新 → 观察 → …

观察 = 获取当前信息与状态
决策 = 根据目标与约束选择下一步
行动 = 调用工具或生成候选结果
检查 = 对照预期核实行动结果
更新 = 记录进展 + 补充信息 + 调整计划

继续执行 = 尚未完成 ∧ 存在可行下一步 ∧ 权限允许 ∧ 预算充足
停止执行 = 已完成 ∨ 需要接管 ∨ 无法继续 ∨ 预算耗尽
```

### 输出验收

```text
输出验收 = 交付物检查 + 完成条件检查 + 证据核对

交付物检查   = 内容齐全 ∧ 格式符合要求
完成条件检查 = 必需验收项全部通过
证据核对     = 完成声明有对应的可核实依据

成功完成 = 交付物检查通过 ∧ 完成条件检查通过 ∧ 证据核对通过
停止执行 ≠ 成功完成
```

“停止执行不等同于成功完成”表示：停止可能是因为完成，也可能是因为受阻或预算耗尽，不能仅凭停止就判定成功。

### 结语

先把这些公式摆出来，后续我慢慢讲，这里主要是梳理一下逻辑，方便后续实践和讨论。

注意：并不是每个环节都要设计这么细，比如说你完全可以不主动设置资源上限，也完全可以设计一个有全部权限的agent，这些很细的环节的出现只是我觉得，在真实的生产环境中，你的确要考虑这些。
